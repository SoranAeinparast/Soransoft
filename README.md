# Soransoft — وب‌سایت آژانس دیجیتال 

وب‌سایت کامل شرکتی/آژانس دیجیتال مارکتینگ با **ASP.NET Core MVC** و **SQL Server**، شامل سایت عمومی فارسی RTL و پنل مدیریت جامع.

## هویت بصری

- **پالت**: سبز `#8EBC40`، متن `#707070`، زمینه کارت `#F1F1F1`، تیره `#2B2B2B`
- **سبک**: نئومورفیسم — سایه دوگانه `6px 8px 15px rgba(0,0,0,.15)` + `inset 2px 2px 10px white` روی همه کارت‌ها، دکمه‌ها و آیکون‌ها (سایه‌حالت فشرده inset در hover)
- **فونت**: IRANSans/Vazirmatn (خودمیزبان در `wwwroot/fonts`)
- **تم روز/شب**: دکمه خورشید/ماه در هدر (`body.dark_mode` — کارت `#2B2B2B`، متن `#A49F9F`، بدون سایه)، انتخاب کاربر در localStorage، پیش‌فرض روز
- **گرافیک هیرو**: کمان‌های تزئینی گوشه + آیکون‌های فضایی شناور با انیمیشن `MoveUpDown`
- **نوار سبز سرویس‌ها** زیر هیرو (`sn-btn-section`، مشابه btnSection مرجع) و **نوار سبز چسبان مشاوره** پایین صفحه (`sn-stick-message`، مشابه stick_message) با نمایش پس از اسکرول
- **فوتر روشن** با عنوان بزرگ سایه‌دار و آیکون‌های اجتماعی شناور نئومورفیک
- بوت‌استرپ و بوت‌استرپ‌آیکون‌ها کاملاً خودمیزبان (`wwwroot/lib`) — بدون وابستگی CDN در اجرا

## معماری (Clean Architecture)

```
Soransoft.sln
├─ Soransoft.Domain          → موجودیت‌ها، Enumها، انتزاع‌ها (بدون وابستگی)
├─ Soransoft.Application     → اینترفیس سرویس‌ها، ViewModelها، منطق orchestration
├─ Soransoft.Infrastructure  → EF Core (DbContext/Configurations/Migrations)، Seeder، FileStorage، پیاده‌سازی سرویس‌ها
└─ Soransoft.Web             → MVC عمومی + Area ابmین پنل ادمین + wwwroot (CSS/JS اختصاصی RTL)
```

جریان وابستگی: `Web → Infrastructure → Application → Domain`

## پنل مدیریت (`/Admin`)

- **داشبورد** — آمار سفارش‌ها/پیام‌ها/مقالات/نمونه‌کارها + کارت‌های سرویس/تعرفه/اسلایدر/تیم/کاربران/فایل‌های رسانه + آخرین رکوردها + نمودارهای Chart.js
- **سرویس‌ها** — CRUD کامل با ویژگی‌ها و مراحل تایم‌لاین
- **نمونه‌کارها** — CRUD + آپلود تصویر
- **مقالات و دسته‌بندی‌ها** — CRUD + وضعیت انتشار + تصویر شاخص + اسلاگ خودکار (فارسی و لاتین)
- **تعرفه‌ها** — مدیریت کامل: بخش‌ها (افزودن/ویرایش/فعال‌سازی/حذف زنجیره‌ای) + پکیج‌ها با همه فیلدها (قیمت/یادداشت/پسوند/مدت/اقساط/پشتیبانی/محبوب‌ترین) + ردیف‌های ویژگی هر پکیج (افزودن/ویرایش/حذف)
- **اعضای تیم** — مدیریت کامل: تصویر، لینکدین، ترتیب، فعال/غیرفعال + حذف نرم
- **کاربران سایت** — لیست کاربران ثبت‌نام‌شده + جزئیات با سفارش‌های کاربر + فعال/غیرفعال (جلوگیری از ورود) + حذف
- **کتابخانه رسانه** — مرور/آپلود/حذف تصاویر + کپی لینک + انتخاب تصویر داخل ویرایشگر TinyMCE + هشدار حذف تصویرِ در حال استفاده
- **مصرف فضا** — نمودار حجم هر پوشه آپلود، تشخیص فایل‌های بدون ارجاع و پاکسازی یک‌جای آن‌ها
- **سفارش‌های پروژه** — مشاهده، تغییر وضعیت، یادداشت مدیر، حذف
- **پیام‌های تماس** — خوانده‌نشده/خوانده‌شده + حذف
- **درخواست‌های مشاوره** — علامت‌گذاری پاسخ‌داده‌شده + حذف
- **منوها** — مدیریت منوی دسکتاپ/موبایل/فوتر + سوییچ فعال/غیرفعال
- **تنظیمات سایت** — گروه‌بندی‌شده + افزودن تنظیم جدید (کلید/گروه/نوع) و حذف تنظیم
- **تغییر رمز عبور** — صفحه اختصاصی ادمین با تأیید رمز فعلی (رمز اولیه Seeder را همین‌جا عوض کنید)

### نکته فنی — جریان ذخیره‌سازی پنل
- ویرایشگر متن TinyMCE مقدار موجود فیلد را از مدل می‌خواند (پارشال `_RichTextEditor` با `for=`) و پیش از Submit همگام می‌شود.
- اکشن‌های ویرایش از الگوی «بارگذاری موجودیت + کپی فیلدهای فرم» استفاده می‌کنند تا فیلدهای خارج از فرم (تصویر، بازدید، تاریخ ایجاد) حفظ شوند.
- `SuppressImplicitRequiredAttributeForNonNullableReferenceTypes` فعال است تا فرم‌هایی که همه‌ی خاصیت‌های موجودیت را ارسال نمی‌کنند، بی‌صدا رد نشوند؛ و همه‌ی شکست‌های ModelState پیام `TempData["Error"]` با جزئیات نمایش می‌دهند.
- **تنظیمات سایت** — گروه‌بندی‌شده (عمومی/تماس/شبکه‌های اجتماعی/درباره)
- **ویرایشگر متن پیشرفته (TinyMCE 8)** — برای مقالات و سرویس‌ها، فارسی/RTL، آپلود و انتخاب تصویر داخل متن

## اجرا

**پیش‌نیاز:** .NET 9 SDK + SQL Server (LocalDB یا کامل)

### روش ۱ — ساخت دیتابیس از اسکریپت SSMS (پیشنهادی برای استقرار)

1. `SSMS` را باز کنید و به سرور وصل شوید (`localhost`، `.

SQLEXPRESS` یا…).
2. فایل **`docs/SoransoftDb_Create.sql`** را باز کرده و کل آن را Execute کنید (F5).
   - اسکیمای پایه و داده‌های عمومی ساخته می‌شود؛ برنامه در اولین اجرا migrationهای پرتال را تکمیل می‌کند.
   - اجرای مجدد بی‌خطر است (idempotent) — داده‌ها تکرار نمی‌شوند.
   - جدول `__SoransoftMigrationsHistory` فقط تا migration پایه پر می‌شود؛ برنامه هنگام اجرا migrationهای باقی‌مانده را اعمال می‌کند.
3. `ConnectionStrings:DefaultConnection` در `Soransoft.Web/appsettings.json` را به سرور خودتان اشاره دهید:
   ```json
   "DefaultConnection": "Server=localhost;Database=SoransoftDb;Trusted_Connection=True;MultipleActiveResultSets=true;TrustServerCertificate=True"
   ```
   (یا با کاربر SQL: `Server=...;Database=SoransoftDb;User Id=sa;Password=***;TrustServerCertificate=True`)
4. `dotnet run --project Soransoft.Web`

### روش ۲ — خودکار با EF Migrations

```bash
dotnet restore
dotnet build
dotnet ef database update --project Soransoft.Infrastructure --startup-project Soransoft.Web
dotnet run --project Soransoft.Web
```

در اولین اجرا مایگریشن‌ها خودکار اعمال و داده‌های اولیه (Seeder) درج می‌شوند.

**ساخت حساب مدیر اولیه:**
- `Security:InitialAdmin:Username` و `Security:InitialAdmin:Password` را با Secret Manager یا متغیر محیطی تنظیم کنید.
- رمز اولیه باید حداقل ۱۲ کاراکتر باشد و پس از اولین ورود تغییر داده شود.

## حساب کاربری کاربران عادی

- دو اسکیم احراز هویت جداگانه: ادمین (کوکی پیش‌فرض) و کاربر عادی (کوکی `Soransoft.User` با اعتبار ۱۴ روز)
- یک `PolicyScheme` بر اساس کوکی موجود، درخواست را به اسکیم مناسب فوروارد می‌کند
- رمزها با `PasswordHasher` (ASP.NET Core Identity) هش می‌شوند
- سفارش ثبت‌شده توسط کاربر واردشده به‌طور خودکار به حساب او متصل می‌شود (`SiteUserId`)
- پنل کاربری: فهرست سفارش‌های خود کاربر، جزئیات هر سفارش با تایم‌لاین وضعیت، ویرایش پروفایل، تغییر رمز
- کاربران فقط به سفارش‌های خودشان دسترسی دارند (بررسی `SiteUserId` در اکشن جزئیات)

## امنیت

- Cookie Authentication برای پنل ادمین + Policy `AdminOnly`
- `ValidateAntiForgeryToken` روی همه POSTها
- اعتبارسنجی سمت سرور (DataAnnotations) + سمت کلاینت (jQuery Unobtrusive)
- اعتبارسنجی فرمت/حجم فایل‌های آپلودی
- فیلتر جهانی حذف نرم (Soft Delete) در EF Core

## پرتال همکاران (`/Partner`)

همکاران (توسعه‌دهندگان و همکاران فروش) با یوزر/پس تعریف‌شده توسط مدیر **فقط از بخش «پرتال همکاران»** در هدر وارد می‌شوند و با «ورود / عضویت» سایت امکان ورود ندارند (سه اسکیم کوکی کاملاً جدا: Admin / UserAuth / PartnerAuth).

### اکانت‌های نمونه (بعد از اولین اجرا)
| نقش | یوزرنیم | رمز | پنل |
|---|---|---|---|
| همکار فروش | `sales` | `Sales@123` | لیدها، قراردادها و اقساط، پورسانت، تیکت فنی |
| مدیر فروش (ارشد) | `salesmanager` | `Sales@123` | دیدن داده‌های همه همکاران فروش |
| توسعه‌دهنده | `dev` | `Dev@123` | برد تسک‌ها، ثبت زمان، مستندات فنی، پروفایل |
| مدیر فنی | `techmanager` | `Dev@123` | تسک‌های همه اعضا |

> ⚠️ بعد از اولین ورود، رمزها را از **پنل ادمین ← پرتال همکاران ← بازنشانی رمز** عوض کنید.

### فراموشی رمز همکاران
از صفحه ورود پرتال، لینک «رمزم را فراموش کرده‌ام» درخواست را در **صندوق ورودی مدیر** (پنل ادمین ← پرتال همکاران ← درخواست‌های رمز، با بج شمارنده) ثبت می‌کند؛ مدیر یا **تایید و تعیین رمز جدید** می‌کند یا **رد**؛ بازنشانی مستقیم از صفحه همکاران هم درخواست‌های باز همان همکار را خودکار می‌بندد. پاسخ فرم همیشه عمومی است (افشای وجود/نبودن نام کاربری ندارد) و هر همکار در هر لحظه حداکثر یک درخواست باز دارد.

### جریان کار
1. فروشنده لید را ثبت می‌کند ← ۲. مدیر از `Admin/PortalLeads` تایید و به قرارداد تبدیل می‌کند (اقساط خودکار + نرخ پورسانت مجزا: درصدی/مبلغ ثابت/پله‌ای) ← ۳. فروشنده درخواست بررسی فنی ثبت می‌کند ← ۴. مدیر تسک را در `Admin/PortalDev` می‌سازد و به توسعه‌دهنده تخصیص می‌دهد ← ۵. توسعه‌دهنده وضعیت تسک را To Do → In Progress → Testing → Done تغییر می‌دهد ← ۶. با تایید هر قسط توسط مدیر، پورسانت فروشنده خودکار به‌روز می‌شود؛ همه‌چیز در `Admin/PortalAnnouncements` اطلاع‌رسانی می‌شود.

### مدیریت اکانت‌ها (ادمین)
`Admin/PortalPartners`: ساخت حساب با نقش (فروش/مدیر فروش/توسعه‌دهنده/مدیر فنی) و سطح دسترسی ارشد، فعال/غیرفعال کردن ورود، بازنشانی رمز، حذف نرم — `Admin/PortalDev/Workload`: مانیتورینگ بار کاری تیم فنی (جلوگیری از Burnout).

## فناوری‌ها

ASP.NET Core MVC • EF Core 9 (Code-First) • SQL Server • Bootstrap 5 RTL • Bootstrap Icons • jQuery • Vazirmatn (فونت) • SkiaSharp (بهینه‌سازی تصویر)

## بهینه‌سازی تصاویر آپلودی

هر تصویر آپلودشده (مقاله/سرویس/نمونه‌کار/اسلایدر/تیم/ویرایشگر/کتابخانه رسانه) به‌صورت خودکار بهینه می‌شود:

- ابعاد بزرگ‌تر از **۱۹۲۰px** متناسب کوچک می‌شوند (هیچ‌وقت بالاسکیل نمی‌کند)
- خروجی با فرمت **WebP (کیفیت ۸۰)** ذخیره می‌شود — حجم معمولاً چند برابر کمتر
- **SVG** (وکتور) و **GIF** (متحرک) بدون تغییر ذخیره می‌شوند
- چرخش EXIF عکس‌های گوشی اعمال می‌شود؛ فایل‌های خراب در لحظه آپلود رد می‌شوند
- سقف حجم ورودی ۲۰ مگابایت (پیش از بهینه‌سازی)
